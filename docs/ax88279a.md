# TimeStick V3 and AX88279A on UNO R3

The development source adds a separate AX88279A register and
transmit-timestamp path. The tested fixture is two classic UNO R3 boards,
each with a MAX3421E USB Host Shield, connected to a TimeStick V3 or an
AX88279A development board. Their Ethernet ports connect directly together.
Both Ethernet devices identify as chip code 15, silicon revision 1, firmware
1.2.9.0, USB VID/PID `0B95:1790`. USB VID/PID alone cannot select this driver:
the older AX88279 also uses it, but has a different hardware clock map.

## Install and run

Use the current repository ZIP or checkout, not the older v0.1.0 release ZIP or
Boards Manager bundle. Install Arduino AVR Boards 1.8.8 and USB Host Shield
Library 2.0 version 1.7.0. Add the repository ZIP as an Arduino library, then
select board **Arduino Uno** and these examples:

- **AX88279AGrandmaster** on the first UNO.
- **AX88279AFollowerPI** on the second UNO.

Both sketches run automatically after power-up. Use Serial Monitor at
**115200 baud, 8N1**. The grandmaster prints Sync and Delay_Resp counts; the
follower prints offset in ns, frequency adjustment in ppb, and path delay in ns.
The plain `Grandmaster` and `FollowerPI` examples still select AX88279, not
AX88279A. Builds check the reported chip code before initializing its PTP map.

From a repository checkout, with Arduino CLI:

```sh
arduino-cli compile --fqbn arduino:avr:uno --library "$PWD" \
  --build-path build/axa-master examples/AX88279AGrandmaster
arduino-cli compile --fqbn arduino:avr:uno --library "$PWD" \
  --build-path build/axa-follower examples/AX88279AFollowerPI
arduino-cli upload --fqbn arduino:avr:uno -p /dev/ttyACM0 \
  --input-dir build/axa-master
arduino-cli upload --fqbn arduino:avr:uno -p /dev/ttyACM1 \
  --input-dir build/axa-follower
```

Confirm port identities before uploading. On the tested Linux host the map is:

| Role | UNO USB serial | Port at test | Ethernet MAC |
| --- | --- | --- | --- |
| Grandmaster | `1453230343235190E071` | `/dev/ttyACM0` | `CC:47:92:00:28:A4` |
| PI follower | `14533303731351B0C090` | `/dev/ttyACM1` | `00:0E:C6:81:79:01` |

The board-to-product mapping was not physically confirmed. Use the UNO serial
or MAC to distinguish roles. Linux `/dev/serial/by-id/` paths avoid port-number
changes. Opening serial can reset an UNO. To record both automatic roles with
coordinated reset, close other serial monitors and use:

```sh
python3 tools/capture_pair.py \
  /dev/serial/by-id/usb-Arduino__www.arduino.cc__0043_1453230343235190E071-if00 \
  /dev/serial/by-id/usb-Arduino__www.arduino.cc__0043_14533303731351B0C090-if00 \
  test-results/axa-pair-new --seconds 300
```

This needs pyserial. It refuses to overwrite a capture directory and sends no
PTP start/stop commands. It releases serial ports at the end, leaving both
firmware roles active. `--debug` toggles detailed diagnostics after reset.

## Validation on this pair

A five-minute capture after paired reset completed **272 exchanges** with
zero exchange timeouts, rejected path estimates, missing RX timestamps, or
discarded packets. Both boards recovered automatically from one startup link
down; the follower reached `s3` at 79.140 seconds of uptime.

The fixed window starting 120 seconds after the first sample contains 152
samples, all `s3`, with a constant reported offset of +16 ns, path delay 26 ns,
and frequency correction 0 ppb. These are quantized internal estimates; a
constant reported value does not establish zero physical jitter or 16 ns PPS
accuracy. See the [raw logs, graphs, build hashes, and test record](results/2026-10-30/ax88279a/README.md).

Both serial ports were released after capture, with automatic grandmaster and
PI follower firmware left running. No host PTP process is required.

## Implementation and bring-up

- Detached-bus sampling every 500 ms recovered full-speed USB enumeration on
  these powered devices. It is restricted to the detached waiting state.
- AX88279A native-mode controls use the USB host library's bounded transfer
  timeout instead of its NAK packet-count limit. Clock reads are deferred until
  native-mode and PHY initialization.
- The Ethernet link is restricted to negotiated **1 Gb/s full duplex**.
  USB transport runs at full speed through the MAX3421E.
- Clock read/set offsets are `0x1010`/`0x1004` in PBus bank `0x12`;
  frequency uses register `0x102c` with nominal addend `0x80000000` and
  period 8 ns. The AX88279 register and 131-byte report path remains separate.
- Request `0xe3` configures the firmware timestamp ring. The vendor host buffer
  is 1,024 bytes; firmware 1.2.9.0 actually returned single 16-byte EP4 records
  in this test. Valid Sync and Delay_Req records had status bytes `0x40` and
  `0x41`. The streaming parser accepts complete, aligned transfers and checks
  status, message type, sequence, and ambiguity before using a timestamp.
- The parser retains under 48 bytes of state, rather than a 1 KB report buffer.
  USB packets and receive aggregates remain bounded for the UNO's 2 KB SRAM.
- The reference driver's 1 Gb/s pipeline adjustments are 80 ns on TX and
  250 ns on RX. These are vendor defaults, not a calibration of this fixture.
- PPS uses clock-enable bit 5, width register `0x103c` set to 500 ms, and
  the output gate at bank `0x0c`, register `0xf8c8`, bit 14. Readback verifies
  configuration only.
- The new PI example uses a 1 ms initial coarse-step threshold. Runtime coarse
  stepping retains the existing 500 ms threshold. Other servo gains are unchanged.

Register definitions and initialization ordering were checked against the
[ASIX Linux driver at revision 42feb1252fe0669845a8d6714bcc77bfc19eea1d](https://github.com/ASIXElectronics/asix-usb-nic-linux-driver/tree/42feb1252fe0669845a8d6714bcc77bfc19eea1d),
particularly `ax_ptp.c`, `ax_ptp.h`, and `ax88179a_772d.c`. The UNO code writes
volatile configuration; it does not update Ethernet firmware, EEPROM, or eFuse.
Original UNO flash and EEPROM were backed up before installation.

## Limits

This is fixed-role L2 PTPv2, domain 42, two-step, E2E, at one exchange per
second. The grandmaster is free-running with an arbitrary epoch, not UTC.
No BMCA, profile compliance, traffic-load validation, or calibrated link
asymmetry is claimed. The seconds implementation is bounded to 32 bits.

Staggered startup or a peer reset can briefly drop the link, cause rejected
clock reads, and trigger reinitialization. Paired reset and autonomous retries
were used during bring-up. The first acquisition may reject path estimates
while the clock is making a large frequency correction. Repeated cold-start,
cable-removal, and long-duration robustness remain to be characterized.

The earlier AX88279 R3/R4 and Saleae measurements do not characterize this new
pair. AX88279A PPS edge alignment has not been independently measured here.
