# First hardware test: 2026-10-12

This report records the initial USB, clock, and Ethernet bring-up. It culminated
in 10/10 verified Ethernet round trips on the replacement AX88279 unit.
Subsequent hardware-timestamped PTP synchronization results are in the
[PTP test report](ptp-test-2026-10-12.md). Earlier failures below are historical.
The original unit was later identified as AX88279A; see the correction below.

## Setup and confirmed results

- Test host: PTPBox, Linux x86_64.
- Arduino: USB ID `2341:0043`, identified as Uno R3, serial port `/dev/ttyACM0`.
- Added the test account to `dialout` to permit serial access.
- Installed an isolated Arduino toolchain under
  `/home/user/.local/share/tinyptp/`, without changing existing PTP services.
- Arduino CLI: 1.5.2-rc.1; AVR core: 1.8.8; USB Host Shield Library 2.0: 1.7.0.
- Read and saved all 32768 bytes of original Arduino flash using avrdude before
  the first upload. This is a flash backup only, not an EEPROM or fuse backup.
- The original probe compiled and uploaded successfully: 7912 bytes flash,
  332 bytes static SRAM.
- The enhanced register diagnostic compiled and uploaded successfully:
  8436 bytes flash, 332 bytes static SRAM. This was subsequently extended with
  the optional ASIX control-read diagnostic described below.

The diagnostic assumes standard UNO host-shield wiring with chip select D10

The TimeStick did not reach USB enumeration. There is no evidence yet about

timestamping through this shield.

## Host Ethernet

`enp179s0f0` carries the host's management connection. `enp179s0f1` is the likely
spare port connected to the TimeStick, but physical cable mapping remains to be
confirmed. It uses `ixgbe` and advertises hardware TX/RX timestamp support with
PTP hardware clock index 15. At inspection it was administratively up, with
no carrier and no negotiated link speed. This alone does not establish whether
the cable, dongle power, or dongle initialization caused the absent link.

Existing ptp4l instances and their clock configuration were left unchanged.
No PTP traffic test or clock adjustment was performed.

returned -1 and all four controller registers again read `00` at 125 kHz,

The output is saved as `test-results/retest-02.log`. Confirm the shield's

At 18:00:16 UTC, another requested retest produced the same initialization

Output: `test-results/retest-04.log`.

## TimeStick enumeration and vendor controls

At 18:05:43 UTC, the TimeStick enumerated at USB full speed (12 Mbit/s host):

- VID/PID `0B95:1790`, bcdDevice `0500`, endpoint-zero packet size 64 bytes.
- Configuration 1: vendor interface, seven endpoints. Bulk IN `0x82` and
  `0x84`, bulk OUT `0x03`, `0x05`, `0x07`, `0x09`, interrupt IN `0x81`.
  Bulk packet sizes are 64 bytes; interrupt packet size is 16 bytes.
- Configuration 2: CDC-NCM, with data endpoints on alternate setting 1.
- Configuration 3: CDC-ECM, with data endpoints on alternate setting 1.
- All configurations advertise 500 mA. This descriptor is a declared power
  requirement, not a measurement of consumption or available supply current.

Endpoint `0x84` corresponds to the AX88279 timestamp-report endpoint in the
supplied driver, but timestamp transfers on it have not yet been tested.

At 18:06:53 UTC, the probe was extended with serial command `v` and uploaded.
The standard AVR build used 9824 bytes of flash and 338 bytes of static RAM.
Selecting vendor configuration 1 and issuing vendor control reads produced:


Each vendor read returned its expected byte count. Samples were separated by

The final build adds zero-initialization of the configuration-check buffer and
was compiled and uploaded successfully: 9836 bytes flash, 338 bytes static RAM.

## PHY and clock initialization, original stick

The original stick (MAC `00:0E:C6:00:40:1B`) established a 1 Gb/s full-duplex
link after native-mode and PHY setup. In the initial sequence, PTP register
writes preceded waiting for Ethernet link. Four-byte readback returned only
the low byte for values such as `0x41080001` and `0xCCCCCCCC`, and the clock
did not advance. Logs: `init-01.log` through `init-03.log`.

The replacement tests below exposed an initialization-order dependency. A
subsequent source comparison also corrected the original chip identification
to AX88279A. Its earlier result does not establish a hardware fault or a USB
library defect. Its different register layout requires a separate driver path.

## Replacement stick

At 18:13:32 UTC, the user swapped the stick. Identification changed as follows:

| Field | Original | Replacement |
| --- | --- | --- |
| MAC | `00:0E:C6:00:40:1B` | `9C:69:D3:2B:A1:2F` |
| USB VID/PID | `0B95:1790` | `0B95:1790` |
| bcdDevice | `0500` | `0400` |
| Vendor endpoints | 7 | 5 |
| Interrupt IN maximum packet | 16 bytes | 8 bytes |
| Declared USB power | 500 mA | 450 mA |
| Chip status / corrected code | `F0` / 15 (AX88279A) | `74` / 7 (AX88279) |
| Silicon revision | 1 | 1 |
| Firmware | Not read | `1.3.16.7` |

The replacement still exposes bulk IN `82`/`84` and OUT `03`/`05`. Its PCB
revision has not been independently confirmed. USB `bcdDevice` is not itself
a PCB revision identifier.

Its clock read (`C0 13`, value `0002`, index `1014`, length 10) initially
returned STALL (`05`). The first PBus write also stalled when issued before
waiting for Ethernet link. After changing the order to native mode, PHY power,
autonegotiation, link wait, then clock access, all four checked PTP registers
read back correctly:

```text

Initialized clock sec(hex)=000000000001 ns=16758400
```

PTPBox's `enp179s0f1` independently reported carrier, 1000 Mb/s, and full duplex.
These results demonstrate a running local hardware clock, not synchronized

Evidence: `replacement-init-01.log`, `replacement-controls-02.log`, and
`replacement-init-03.log`. The earlier STALL was not evidence of missing PTP
support. The probe now waits for link and checks clock request success before
writing PTP registers.

## Bidirectional Ethernet test

At 18:20:10 UTC, the replacement passed the transport diagnostic. The UNO sent
10 distinct 60-byte Ethernet frames using experimental EtherType `0x88B5`.
The Linux peer bound only to `enp179s0f1`, validated each payload and sequence,
and sent a unicast echo. The UNO accepted each echo only after checking the
ASIX receive metadata, destination, EtherType, sequence, and payload pattern.
Both sides reported 10/10. A successful USB write alone was not counted as a
successful Ethernet test.

The final sketch compiled and uploaded with Arduino AVR core 1.8.8 and USB
Host Shield Library 2.0 version 1.7.0: **14796 bytes flash, 587 bytes static
SRAM**. The remaining 1461 bytes are available for stack and dynamic use;
actual maximum stack usage has not been measured. The receive diagnostic
stores at most 192 bytes, drains larger aggregates, and accepts only one
60-byte frame per aggregate. It is not a complete receive driver and has not
been load-tested.

The first two transport attempts stopped before transmitting because the
probe's speed check was wrong. PHY register 17 did not use the older PHY's
bit layout, and the interrupt duplex field did not match that assumption.
The final code checks the interrupt speed and resolves full-duplex capability
from the standard MII local/partner gigabit advertisement registers. It accepts
only the observed 1 Gb/s full-duplex link.

Evidence: `replacement-ethernet-03.log` and `replacement-peer-03.log`.
The final code is installed on the UNO. No host clock or existing PTP daemon
configuration was changed, and no long-running test process is required.

To repeat, start the peer on PTPBox in one terminal:

```sh
sudo python3 /home/user/tinyPTP/tools/link_peer.py enp179s0f1 --seconds 60
```

Then, in another terminal, use a fresh log filename:

```sh
python3 /home/user/tinyPTP/tools/capture_serial.py \
  /dev/ttyACM0 /home/user/tinyPTP/test-results/ethernet-repeat.log \
  --reset --command et --seconds 45
```

`e` performs initialization; the queued `t` runs the test afterward in the
same serial session. Opening a separate serial session would reset the UNO.
The next missing pieces are enabling the PTP packet parsers, receiving and
correlating hardware TX/RX timestamps, clock adjustment, and the PTP exchange
and servo. These results do not yet demonstrate PTP synchronization.

## Chip identification correction

The older TimeStick driver used chip mask `0x70`, which incorrectly collapsed
status `F0` to code 7 in the first probe. The current official ASIX driver uses
mask `0xF0` and defines code 15 as AX88279A. Consequently, the original stick
was AX88279A, while the replacement is AX88279. The probe now uses the corrected
mask and refuses AX88279 initialization on AX88279A. This distinction affects
PTP registers and transmit-timestamp format; it is not merely a USB descriptor
revision difference. The original stick has not been retested with an AX88279A
driver.

Reference: [official ASIX driver](https://github.com/ASIXElectronics/asix-usb-nic-linux-driver),
revision `42feb1252fe0669845a8d6714bcc77bfc19eea1d`, `ax_main.h` and `ax_ptp.h`.
