# UNO to PTPBox hardware-timestamped PTP test

The UNO successfully synchronized the attached AX88279 TimeStick clock to
PTPBox's spare Ethernet NIC using hardware-timestamped PTP. The principal
145-second serial capture contains 131 complete exchanges. Over the final
40 exchanges, the reported offset RMS was **13.13 ns**, with extrema
**-29 ns to +22 ns**. This is an internal PTP offset estimate, not an independent
measurement of absolute time or PPS accuracy.

## Setup

- UNO R3, ATmega328P, MAX3421E shield, full-speed USB (12 Mb/s).
- TimeStick: AX88279 revision 1, firmware `1.3.16.7`, MAC `9C:69:D3:2B:A1:2F`.
  Its exact PCB revision remains unconfirmed.
- PTPBox: `enp179s0f1`, ixgbe, 1000 Mb/s full duplex, hardware clock `/dev/ptp15`.
- Linux `ptp4l` 4.4, fixed master, hardware timestamps, `free_running 1`.
- IEEE 1588v2 over Ethernet (`0x88F7`), domain 42, two-step Sync, E2E delay,
  one Sync per second. Master port identity `0c9d92.fffe.c58332-1`.
- The UNO runs the fixed-peer client, timestamp correlation, offset calculation,
  and integer PI servo. The Linux host does not calculate the client servo.

No existing PTP service or host system-clock configuration was changed. The
host NIC clock was the reference; its traceability to UTC was not assessed.
The TimeStick's volatile clock and frequency registers were adjusted. Its
flash, EEPROM, and eFuse were not written.

## Timestamp and initialization findings

The ASIX RX aggregate contains hardware ingress timestamps for Sync. The
TimeStick's endpoint `0x84` delivers 131-byte TX reports over three full-speed
USB packets: 64, 64, and 3 bytes. Each report has two banks of five 13-byte
records and a final bank selector. The client matches Delay_Req message type
and sequence number to its hardware egress timestamp; it never substitutes
USB completion time for a packet timestamp.

The earlier clock initialization did not survive the later MAC setup on this
unit. Initial PTP attempts therefore lacked TX reports or returned zero-valued
timestamps. The working order is PHY/link, Ethernet MAC, then the complete PTP
clock/report/parser setup. The code checks clock progression at this final
stage and rejects zero hardware timestamps. A brief bounded retry handles
clock-control requests that temporarily stall just after PHY link-up. A
restart test also returned the invalid PBus sentinel `DEADBEEF`, which the
register and clock checks rejected. A 500 ms settling interval after PHY
link-up and nanosecond-range validation before clock setup were added for
that transition. These are bounded startup checks, not a power-cycle
reliability certification.

The original five-record/131-byte timestamp format works at full speed. The
smaller four-record buffer considered during diagnosis was not needed or
applied. The report is assembled incrementally with its bank selector processed
only after the complete report has arrived.

Before enabling the servo, 14 complete exchanges in `ptp-observe-07.log`
showed approximately 123 ppm relative drift and roughly 0.96 microseconds of
estimated path delay. All four timestamps were present and correlated.

Capture: `ptp-servo-01.log`, started 2026-10-12 at 18:32:20 UTC
(11:32:20 AM America/Los_Angeles), with a requested 145-second capture window.

| Complete exchanges | 131 |
| Initial coarse clock steps | 1 |
| Exchange timeouts | 0 |
| Rejected path measurements | 0 |
| Missing Sync hardware timestamps (last status) | 0 |
| Steady-state window | Samples 92 through 131 |
| Mean offset | -6.375 ns |

| Maximum absolute offset | 29 ns |

The initial coarse step aligns the epoch. Its USB latency leaves a residual
phase error; subsequent hardware-timestamp measurements drive a bounded PI
frequency servo. The initial residual was approximately -846 microseconds.
The reported offset reached tens of nanoseconds around sample 90. The final
40-sample window was selected after acquisition; it does not describe startup
performance or an independently calibrated accuracy bound.

The last status at sample 130 counted 14 discarded RX aggregates. This counter
includes empty, oversized, or unsupported aggregates, so it is not a PTP loss
counter. There were no failed complete PTP exchanges in this run. Background
traffic and heavier load have not been characterized.

## Scope and limits

This is a fixed-peer experimental client, not a complete general-purpose PTP
implementation. There is no BMCA, master failover, profile compliance claim,
UTC/leap-second handling, P2P/gPTP, management plane, or calibrated PHY/link
asymmetry. It accepts the configured two-step master, domain, source port
identity, and matching message sequences. It times out incomplete exchanges,
checks correction fields, and clears pending measurements after coarse steps.

Receive aggregation is bounded to 256 bytes, and larger aggregates are drained
and discarded. Time fields use a bounded 32-bit seconds epoch ending in 2106;
nonzero upper seconds bits are rejected. Static memory fits the UNO, but maximum
runtime stack use has not been measured. PPS routing was not enabled or tested.

The earlier original stick is AX88279A, not AX88279. A corrected chip-code mask
now prevents this AX88279 register sequence from being applied to it. Supporting
that device requires its separate register and timestamp path.

## Reproduction and verification

The master configuration is `configs/ptpbox-master.conf`. The Linux launcher
`tools/run_ptp_master.sh` verifies the spare NIC MAC, takes an exclusive lock,
uses runtime paths allowed by the installed AppArmor policy, and runs a bounded
master session. See the README for the two-terminal procedure.

Analyze a saved capture with:

```sh
python3 tools/summarize_ptp.py test-results/ptp-servo-01.log --tail 40
```

Timestamp arithmetic tests cover second rollover, negative offsets, fractional
correction fields, large initial epoch differences, and rejection of invalid
nanoseconds and unsupported seconds. They passed with address and undefined
behavior sanitizers:

```sh
c++ -std=c++11 -Wall -Wextra -Werror -fsanitize=address,undefined \
  tests/ptp_math.cpp -o /tmp/tinyptp-math-test
/tmp/tinyptp-math-test
```

Raw logs remain in the ignored `test-results/` directories on PTPBox and in the
local checkout. The firmware was built with AVR core 1.8.8 and USB Host Shield
Library 2.0 version 1.7.0. The final build size and restart validation are
recorded below.

Protocol references:
[TimeStick driver](https://github.com/Time-Appliances-Project/TimeStick/tree/4c2935a1f723f8ec66fc3a3b4fb6a246b9de7c6e/TimeStick2/DRV),
[current ASIX driver](https://github.com/ASIXElectronics/asix-usb-nic-linux-driver/tree/42feb1252fe0669845a8d6714bcc77bfc19eea1d),
and [LinuxPTP configuration documentation](https://www.linuxptp.org/documentation/ptp4l/).

## Final firmware and restart validation

The final installed image uses **23470 bytes of flash** and **917 bytes of
static SRAM**, leaving 1131 bytes for stack and dynamic use. A restart with
the settling check enabled (`ptp-final-check-02.log`) again established
hardware-timestamped PTP and converged without exchange timeouts. This shorter
check is distinct from the 131-exchange steady-state dataset above.

Additional protocol tests passed under ASan and UBSan. They check domain and
source filtering, missing RX timestamps, incorrect Follow_Up sequence numbers,
incorrect Delay_Resp requester identities, Delay_Resp arriving before the TX
report, the selected report bank across 64/64/3-byte USB packets, timestamped
RX aggregation, and 20000 malformed aggregate inputs.

```sh
c++ -std=c++11 -Wall -Wextra -Werror -fsanitize=address,undefined \
  tests/ptp_protocol.cpp -o /tmp/tinyptp-protocol-test
/tmp/tinyptp-protocol-test
```

The final restart capture completed 86 exchanges, with one initial coarse
step, zero exchange timeouts, and zero rejected path measurements. Its last
10 offsets ranged from +13 to +59 ns (42.24 ns RMS), still finishing acquisition.
The serial capture sent `x` at completion to stop the client and restore nominal
frequency. The dedicated master was then terminated; the five-second launcher
smoke test also entered MASTER and exited normally. Existing PTP services
remained running. No test daemon was left running.
