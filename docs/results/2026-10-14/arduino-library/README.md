# Arduino library installation and build validation

The 0.1.0 library package reorganizes the existing tested implementation into
`src/detail/`, adds a small `TinyPTP.h` entry point, and supplies seven separate
Arduino sketches. It does not change the protocol, driver register sequences,
PPS configuration, or servo equations. Original headers are preserved apart
from a configuration comment; the old sketch body becomes the internal
application with `begin()` and `poll()` entry points. Internal definitions now
live in the `tinyptp_detail` namespace.

The final release ZIP was installed with Arduino CLI's ZIP-library installer
into an isolated sketchbook on PTPBox. USB Host Shield Library 2.0 was installed
separately through the library command. Example discovery listed all seven
sketches. Every example was compiled for `arduino:avr:uno` without role/servo
compiler flags, using its own `.ino` configuration. The shared existing core
installation supplied Arduino AVR Boards 1.8.8; USB host version was 1.7.0 and
CLI version was 1.5.2-rc.1. This exercises Arduino's library discovery and build
tools; the graphical IDE upload buttons were not exercised remotely.

The follower sizes match the previous standalone builds. Maximum runtime
stack usage is not measured, and the Kalman and linreg flash margins remain
small. The original `tools/build_roles.sh` workflow also compiles both roles
with the explicit library path and compiler overrides.

Eight native C++ test programs passed with address/undefined-behavior
sanitizers, including math, protocol, serial logging, PPS, and all servo tests.
The protocol harness additionally passed for all five follower servo selections.
Seven Python analysis tests passed. No firmware was uploaded and no live serial
port was opened for these packaging checks. The previously installed PI
follower and grandmaster images were left unchanged.

Individual compile logs are retained alongside this report. Firmware hashes
here identify build artifacts, not newly installed hardware images. The release
ZIP is generated by `python3 tools/package_library.py`, which includes only
metadata, library headers, examples, and the IDE guide. All archive entries
have fixed timestamps for reproducibility. The larger GitHub source ZIP also
uses a valid library layout but includes the historical data archive.
